## 重新理解

Pixel 是面向生成模型的创作环境，默认只呈现作品的画面与时间。无按钮不能退化为“图标按钮少一些”，像素风也不能变成“放一张复古主题图”。界面和文本都围绕真实对象、真实数据及此时适用的能力。

一个能力只有一条标准 GUI 语义路径。双击进入对象，右键发现/执行当前 Action，拖拽表达明确来源与目标的关系；同一对象语法的键盘或辅助技术触发不成为另一套功能路径。模型语义与字段由插件声明，所有字体、菜单、导航、选择、反馈和提交由宿主管理。

用户指出主页面找不到素材库入口，并明确要求预览栏右键进入。因此 1.2 将唯一入口改为主 Viewer 右键 → 素材库，空预览或已有输出均可。它是 P03 的局部导航例外，只打开素材上下文，不提交业务 Action；旧的项目详情入口删除，项目标题双击仍只进入项目对象详情，不增加常驻控件。

用户进一步指出素材库打开后主窗口被锁定，要求共同基类和相互拖拽。1.3 明确 workspace 与 library 为独立非模态工作窗口，共用 `DesktopWindowHost` 和前端 `PixelWindowHost`。素材库根不是详情导航 frame，打开或最小化库不禁用主窗口；库根 Esc 关闭。对象详情是所属窗口的局部认知空间，每个窗口仍只有一条详情 path 和一个 ModalHost，继续进入替换顶部内容，Esc 返回一层。库内详情仅隔离库，主窗口继续工作；真实 Asset 放置/引用及 Item 保存复用通过可信窗口间会话提交原 Action，不解除局部详情隔离。

Project State + Action System 是中心。GUI 已通过共享执行器提交；后端诊断 CLI 使用模型执行内核，但正式项目 CLI / Agent 适配器仍待实现。原文里的命令、World Model、生成历史等是语义举例或扩展方向，本次不据此虚构已完成的能力。

| 工作区常驻素材库、类型筛选、版本色板、手势说明、配置及 revision | 作品优先；复杂度按上下文出现 | 默认仅 Viewer + Timeline；素材库通过上下文进入；保留必要窗口控制及相关状态反馈 |
| 用户指出主页面找不到素材库入口，要求预览栏右键进入 | 用户明确需求；唯一入口；P03 局部导航例外 | 1.2 改为主 Viewer 右键 → 素材库，空预览及已有输出均可；1.3 直接打开独立非模态工作窗口，删除项目详情旧入口，不提交业务 Action |
| 空 Viewer 星空与音频人造波形 | 像素服务于确定性；作品优先 | 移除主题装饰和非媒体数据波形；只显示真实媒体或简短空状态 |
| fresh project 自动写入三条时间线及示例提示词 | 用户意图；作品先于工具 | 新项目为空；示例只在明确测试 fixture 中构造，既有项目保持完整 |
| timeline.create 隐式创建首个 Item | 一能力一语义；Asset → Timeline 创建 Item | 创建模型只生成空 Timeline；右键 → 新建时间线 → 模型保持完整入口 |
| 取消自动内容后，无外部媒体的新项目无法开始生成 | 创作闭环；固定单路径；右键承担创建 | 明确两个业务语义：空白时间位置右键创建无输出的模型原生草稿；Asset 拖入时间位置放置已有媒体。各有唯一入口和严格参数，共用创建与校验内核 |
| 不支持引用的模型显示参考区和“不支持”说明 | 语义不适用能力不出现 | 仅支持引用且已有关系/合法拖拽时出现；Wan 首帧模式上限与后端一致 |
| 素材库打开后锁住主窗口，库内镜像关系面替代真实拖拽 | 工作窗口并行；详情局部隔离；拖拽表达关系 | 1.3 复用共同窗口宿主，库与主窗口非模态并行；删除镜像关系面，库 Asset → 主 Timeline 放置/引用、主 Item → 库复用经可信 broker 走既有路由和 Action |
| 文档把诊断 CLI 与正式项目入口混为一谈，或把已实现的 GUI/outbox 写成待实现 | GUI / CLI / Agent 共用动作；实现状态诚实 | 明确诊断与正式适配器边界，同步核心架构、模型接入及桌面说明 |
| 时间指针只画在所选 Item 起点，无法定位和拖动 | 作品中的时间定位；局部交互状态 | 标尺点击及手柄拖动改变窗口本地播放位置，驱动实际媒体预览；定位不移动 Item、不提交 Action、不写项目 |
| 原生拖动标题栏遮挡窗控，详情最小化后缺少恢复入口 | 必要窗口控制；Modal 隔离 | 窗控进入标题栏内的 no-drag 插槽；详情显式注册任务栏入口，最小化与恢复始终保留父窗口隔离 |
