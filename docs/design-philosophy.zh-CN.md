# Pixel 设计哲学与架构约束

基线版本：1.5

生效日期：2026-10-09
来源：《生成视频软件理解》中的产品讨论、用户补充的[哲学原文](sources/product-philosophy.2026-10-08.zh-CN.txt)，以及当前核心架构设计。原文作为历史来源保存，本文是唯一产品规范；原文中的示例不等于全部功能已经实现。

这份文档定义 Pixel 在增加功能、接入模型、重做界面或调整技术栈时需要保持的产品原则。它是功能设计和架构评审的依据；具体类型、类名、事务协议与实现状态见 [核心架构设计](core-architecture.zh-CN.md)。

**Pixel 让用户围绕作品中的对象工作，通过少量稳定的交互规则完成创作。可预测性是目标，无按钮、固定单路径和渐进披露是实现这一目标的约束。**

把功能从默认界面拿掉，把能力放进对象、Action、上下文和语言。无按钮是架构约束，极简是手段；用户面对什么对象、此时什么动作适用，必须始终可预测。本轮理解与修正证据见[哲学对齐记录](philosophy-alignment.zh-CN.md)。

## 1. 作品优先于工具（P01）

默认主工作区只有 Viewer 和 Timeline，即作品的画面结果与时间结构。窗口保留当前项目标题和必要原生窗口控制；不常驻资产库、筛选器、模型面板、版本/色板、手势教程、配置提示或调试信息。素材及其他能力通过对象上下文逐层出现；失败、提交和真实任务进度只在相关状态下出现。

新项目为空，用户未创建的模型时间线、片段、提示词和结果都不预置。空 Viewer 只说明尚无可用结果，不用示例星空、假波形或其他主题装饰占据作品空间。已有项目中的真实数据不得因风格或哲学修正被自动清理。

“无按钮设计”意味着不建立常驻操作按钮、工具栏或功能面板这一套入口。不能把按钮改成图标、悬浮操作条或可点击文字，就绕过这项约束。详情中的字段编辑、菜单项、导航反馈和进度状态仍由统一宿主提供。

新增功能先确定它作用于哪个对象，以及用户何时需要它，再确定入口。默认界面不因为能力增加而持续长出控件。

## 2. 一个业务能力只有一条标准 GUI 路径（P02）

每个能力先登记业务语义和标准入口，再实现交互。同一能力不能同时出现在右键、拖拽、工具栏和详情操作按钮中。更换 Action 名称也不能把重复入口包装成不同功能。

一条拖拽关系只表达一个业务动作，不能依靠弹出选项、修饰键或临时状态，让同一次 drop 在“插入、替换、引用、复制”之间猜测。片段本体与片段边缘是不同的手势来源；不同目标可以表达不同关系。

GUI、CLI、Agent 是同一能力的不同表达方式，共用 Action，并不要求用户只能使用一种输入方式。键盘与辅助技术可以触发同一对象语法，例如进入详情、打开上下文菜单、返回上一层；这些等价触发服从相同语义和作用域。

## 3. 双击进入，右键执行，拖拽建立关系（P03）

| 交互 | 稳定含义 | 设计要求 |
| --- | --- | --- |
| 双击 | 进入当前对象的详情 | 对象种类改变时，进入语义保持一致；时间线左侧配置入口有下述明确例外 |
| 右键 | 发现并执行当前上下文的离散命令 | 菜单来自对象、状态和权限，不能是完整功能树；素材库入口有下述明确导航例外 |
| 拖拽 | 通过来源与目标表达空间操作或关系 | 一组明确的来源与目标只映射到一个动作 |
| 字段编辑 | 修改当前对象的一个明确属性 | 经 Action 提交，宿主统一提交时机和失败反馈 |
| Esc / 返回 | 退回一层详情 | 不关闭整条导航路径，也不暗中提交业务动作 |

当前产品的标准路径如下。这是产品约束表，不表示所有路径已经实现。

| 来源或上下文 | 标准目标或路径 | 唯一含义 |
| --- | --- | --- |
| 项目文件或项目文件夹 | 拖入主窗口 | 进入该位置的项目；空文件夹初始化为空项目 |
| 外部媒体文件 | 拖入资产库 | 导入可复用资产 |
| 外部媒体文件 | 拖入普通媒体时间线或 Timeline 空白区域 | 一次导入并放置；空白区域创建对应视频、音频或图片轨道 |
| 主工作区 Viewer（空预览或已有输出） | 右键 → 素材库 | 进入当前项目的素材库，属于局部导航 |
| Timeline 区域空白处 | 右键 → 新建时间线 → 选择类型 | 创建该类型的空 Timeline；包含本地文本、普通媒体和生成模型 |
| Timeline 左侧名称区域 | 单击 → 时间线详情 | 生成轨道编辑新片段继承的默认配置，本地轨道呈现其声明的详情 |
| Timeline 左侧名称区域 | 右键 → 刷新时间轴默认配置 | 将当前默认配置明确应用到已有片段 |
| 已有 Timeline 的空白时间位置 | 右键 → 新建生成草稿 | 创建无输出的模型原生草稿 |
| 纯文本 Timeline 的空白时间位置 | 右键 → 新建文本片段 | 创建可编辑、带时间区间的参考文字 |
| Asset | 拖入 Timeline 的时间位置 | 创建 Item；视频插件中可表现为 Clip |
| Item 本体 | 拖到当前 Timeline 的新时间位置 | 移动 Item |
| Item 边缘 | 拖动起点或终点 | 修改时间范围 |
| Item | 拖入资产库 | 保存为可复用资产 |
| Asset | 拖入 Item 的引用区域 | 建立 Reference |
| 对象 | 双击 | 进入该对象详情 |
| Item | 右键 | 生成、重新生成、复制、分割、删除等适用命令 |
| Viewer 输出 | 拖到窗口外 | 导出当前可用结果 |

创建模型 Timeline 只创建空 Timeline，不同时隐式创建 Item。空白时间位置右键的 `item.createDraft` 创建没有输出、没有引用的模型原生生成草稿；Asset → Timeline 的 `item.create` 要求已有资产，并把其真实媒体作为新 Item 的输出。两者分别是描述新结果与放置已有结果，不能在同一 drop 上切换，也不能给任一语义增加第二条 GUI 路径。它们共用插件构造、位置校验和事务规则。领域 Action 可以被正式 CLI / Agent 显式调用，但不能通过诊断工具成功冒充已实现项目入口。

项目拖入的目标是主工作窗口根，表达进入外部位置的项目：已有 Pixel 项目文件或目录在原位置打开；真正的空文件夹在该位置初始化空项目并打开。结果由容器的已有内容确定，不弹出“导入、合并或新建”选择，也不借修饰键改变含义。普通非空素材目录、未知或空文件拒绝，并保留当前项目。项目文件打开与外部媒体放置依据来源类型及固定目标区分，不解释为合并两个项目。浏览器开发版不能取得可信本机目录位置，因此明确提示使用桌面版，不模拟已经打开本地项目。具体文件校验与会话边界见[项目打开与系统拖拽](project-open-and-system-drag.zh-CN.md)。

按用户明确要求，1.5 增加纯文本以及普通视频、音频、图片轨道。它们使用同一 Timeline 插件基类、整数时间壳及 Action，作为本地语义存在，不伪造生成模型。纯文本用于通用笔记、分镜和提示词参考，允许同一时刻有多条笔记，不能生成、放置媒体或自动成为供应商输入。外部 Agent 通过只读、有界文本投影读取时间、正文和对象身份；项目文本是数据，不能自行改变 Agent 的权限或执行指令。

1.5 按“用户直接拖入普通媒体轴”的要求扩展原媒体只在库导入的基线：系统媒体 → 普通媒体轨道是“导入并放置”，系统媒体 → Timeline 空白区域是同一放置路径下创建对应的本地轨道；两者共用一条 `external.media → timeline.position` 路由和一个原子 Action。库导入仍是登记可复用素材，结果不包含片段，不能把二者当成同义入口。目标已有轨道时只接受同媒体类型的本地轨道；不借修饰键或弹出选择把 drop 改成引用、替换、模型生成或项目切换。文件格式在后端按真实内容校验；新建、素材登记和片段放置共同提交，失败不留下空轨道或项目素材记录。具体取舍和评审见[本地时间线与扩展边界](local-timelines-and-extension.zh-CN.md)。

按用户明确要求，Timeline 左侧名称区域单击进入默认配置。这是限定于该区域的 P03 导航例外；移除同一区域双击入口及 Item 详情中的同义跳转，不把单击变成所有对象的通用详情手势。键盘 Enter 是同一入口的等价表达。详情字段仍由共同宿主提交，不增加常驻参数面板或保存按钮。

时间线默认配置描述新片段应继承的模型参数及生成设置。修改默认值保留已有片段的原配置；已有片段只有通过左侧右键“刷新时间轴默认配置”才采用当前默认值。刷新保留正文、提示词、位置及素材关系，不自动启动生成；实际生成输入改变时，使对应旧生成结果失效，保留已放置的真实素材。正文、邻接文本和素材引用不属于批量默认值。

按用户对入口可发现性的明确要求，资产库的唯一进入路径改为主工作区 Viewer 右键 → 素材库，空预览与已有输出均可使用。该菜单项是 P03 的局部导航例外：只进入项目素材上下文，不修改项目，不提交业务 Action，也不构成把所有详情入口改为右键导航的通用规则。项目标题双击仍进入项目详情，但其中不再保留素材库入口；不增加常驻按钮或第二条打开路径。

素材库是独立、非模态的工作窗口，与主工作窗口并行；打开素材库不能锁定主窗口。桌面窗口由共同 `DesktopWindowHost` 组合 `BrowserWindow` 管理，前端复用 `PixelWindowHost` 统一视觉、窗口控制与生命周期；浏览器开发版使用同源独立 popup（`?window=library`），复用同一 App 与窗口外观。各工作窗口持有自己的局部交互状态，读取同一后端项目投影。素材库 Asset → 主 Timeline 时间位置放置、素材库 Asset → Item 引用区域，以及主 Item → 素材库复用，通过可信跨窗口拖拽会话建立真实对象关系，继续使用原来的 Action 与角色路由。不在素材库中复制时间线或输出对象作为替代拖拽面，不增加新的 GUI 命令。

独立工作窗口与对象详情不同。素材库列表是工作窗口根，根层没有 `ModalNavigator` frame；库内双击对象在库 document 中进入一个 ModalHost 的顶部详情 path，只隔离库自身的背景及旧详情层，主窗口仍可交互。Esc / 返回退出详情回到库，库根的 Esc / 关闭操作关闭该工作窗口。合法跨窗口 drop 经宿主检验来源、目标与各自作用域。非模态工作窗口之间建立关系，无需解除任何对象详情的隔离。

引用关系只登记一条 Asset → Item 引用区域（`item.reference`）语义路由。对象详情可以呈现该引用区域，但不能把详情字段另注册为第二条“添加引用”入口。代码中的候选角色名称不自动成为合法产品路径。

模型不作为可排列、可拖拽的工作区对象存在。不能增加“拖模型创建时间线”或常驻模型栏。Asset 拖入 Item 也不能突然解释为替换内容；复制或重新生成不借用拖拽路径。没有登记的组合默认无效。

字段修改按宿主统一约定即时提交，或在明确的编辑完成时提交，不另增“保存 / 应用”按钮。Esc 只控制详情导航；尚未提交的编辑如何离开，由宿主统一定义并明确反馈。

Viewer 的导出手势保持唯一。需要耗时准备时，宿主先准备文件、显示准备状态，文件可用后才允许拖出；不能为了补实现问题再添加另一套导出按钮或菜单入口。

## 4. 复杂度按上下文出现（P04）

用户进入对象之前，不提前展开该对象的全部参数。右键菜单提供当前相关的能力，详情展示当前对象需要的信息，子对象通过进一步进入逐层展开。

每个工作窗口拥有独立的详情导航 host，详情是一条路径。双击子对象推进一层，Esc 弹出一层；一个详情宿主只使用一个 ModalHost，打开新层不创建嵌套 Dialog 树。只有顶部详情层可以接收编辑、菜单和 drop，隔离范围是所属工作窗口的背景及旧层，不是整个应用的所有窗口。

资产库、项目设置和模型选择也遵循上下文披露。资产库作为独立工作窗口出现不等于打开对象详情，不应锁定主工作窗口。不能为了方便拖拽，临时解锁某个窗口内已经被对象详情隔离的背景。跨窗口关系通过共同窗口宿主、可信拖拽会话和当前合法目标完成。对象被删除后，详情退回仍存在的祖先，选择与临时交互状态也应清理。

## 5. Project State 与 Action System 是系统核心（P05）

```text
GUI ───┐
CLI ───┼─→ 可信适配器 → Action System → 项目权威状态
Agent ─┘                                     ↓
                              快照与事件 → 前端只读投影
```

业务能力由 Action 表达，GUI 手势把业务意图转换为 Action。CLI 与 Agent 直接调用同一协议，不通过模拟点击和拖拽获得核心能力。项目业务逻辑必须能够在没有 React 和窗口的环境中执行。窗口及详情导航属于宿主局部交互状态；Viewer 右键进入素材库不为纯导航制造项目 Action。

后端持有项目权威状态，统一执行输入校验、权限、业务规则和提交。前端投影不能成为第二份可自由写入的项目数据库；选择、Modal path、hover、视口和拖拽预览是局部交互状态，不写入项目文件。

GUI 菜单和 Agent 能力发现共用语义目录及规则。前端可以根据快照提示可用性，后端在执行时仍重新校验。不另建一套仅供 Agent 使用的业务处理器，也不把模型逻辑写进组件事件回调。

## 6. 插件提供语义，宿主提供交互（P06）

Timeline 是内容语义在时间维度上的表达，既包含本地文本及普通媒体，也包含生成模型。视频、音乐、对白等可以拥有不同的 Item 与参数语义；本地轨道不能为了复用而伪造模型，新模型不能被迫套进 VideoClip 的继承树。

| 插件声明 | 宿主统一负责 |
| --- | --- |
| Item 种类、字段、默认值、schema 和时间约束 | 字段控件、布局、焦点、选择和错误显示 |
| 模型能力、动作语义与适用条件 | 菜单、唯一 GUI 路径与 Action 执行 |
| 可接受的引用关系 | 拖拽手势、命中、预览与作用域 |
| 数据版本及迁移规则 | 版本检查、迁移提交和兼容性展示 |

插件不能自行修改项目、另开 Modal、增加工具栏或建立自己的样式系统。业务扩展不等于交互规则扩展。

像素视觉服务于确定性：固定栅格、清晰边界、统一间距、有限颜色，以及明确的 hover、selection、focus 和任务状态。Typography 使用统一的 Title、Description、Body 角色。字号、颜色和具体 token 可以调整，但插件仍必须使用宿主的设计系统；装饰不能牺牲可读性和键盘焦点反馈。

## 7. 用户意图在异步过程中保持有效（P07）

一个动作完成一次明确提交。拖动和 hover 只产生预览，不启动生成，不悄悄写项目。失败需要有可理解的反馈，不能用乐观显示把失败伪装成成功。

长时间运行的生成与导出是独立任务。生成先保存产物，再通过受控 Action 关联到 Item；结果必须仍属于当前目标、当前请求和相关输入。用户修改、删除、取消或重新生成后，旧结果不能覆盖新的意图。无关时间线的编辑不应让结果失效。

撤销作用于项目编辑。解除输出关联可以撤销，已发生的外部模型调用、费用和文件写入不能被假装撤回。任务进度不进入编辑撤销历史；挂载和撤销挂载不立即删除产物。

权限由可信入口注入，不能信任前端传来的身份和权限。跨窗口拖拽、重复请求和晚到结果也必须经过宿主的验证边界。具体 revision、幂等、attempt 和事务约定见架构文档。

## 8. 数据和能力也逐步披露（P08）

模型搜索、资产查询、动作发现和 Agent 返回结果采用有界查询，支持按需要分页、筛选、排除和继续查找。默认返回少量相关信息，避免把完整能力表或大量结果一次塞进界面和 Agent 上下文。

信息共享明确结构：Title 说明对象是什么，Description 说明用途，Body 展示必要数据。暂不可执行的能力保留状态及原因；语义不适用的能力不出现。Loading、失败和空状态由宿主一致表达。

“存在但暂不可执行”与“对当前对象根本不适用”必须区分。音频模型不支持图像引用时不显示引用管理或“不支持引用”的常驻区域；支持引用的对象只在已有关系或合法拖拽上下文下呈现相应内容。引用角色和数量限制以同一模型语义为准。

具体查询上限是实现参数，可以按需求调整；有界、可继续、可细化的查询原则需要保留。

## 9. 架构承载约束，复杂度随证据增加（P09）

稳定的数据使用可序列化接口；有共同执行流程的行为扩展点才使用基类。React 视图使用函数组件，宿主服务优先组合。领域核心不依赖 UI 框架，项目文件不保存类实例、DOM、回调或 provider 凭证。

交互规则集中在宿主系统：Action、Modal 导航、上下文能力和 DragRegistry。不能让每个组件或插件各自实现一套行为。GUI 路径注册、公共不变量和结果守卫用于承载这些约束；人工评审还要识别不同 Action 名称背后的重复业务语义。

先完成单机、单项目、单模型的完整闭环，再根据实际瓶颈扩展。Electron、React、Zustand、Radix、dnd-kit、DOM 时间线及未来的渲染方案是实现选择，可以替换。替换后仍需维持前面的产品语义、权威状态和依赖方向，不能让库自带的交互反过来决定产品。

## 10. 如何判断是否发生漂移

新增功能或修改核心边界时，评审回答以下问题；简单变更只写相关项，无需建立额外审批流程。

1. 它作用于什么对象？唯一标准 GUI 路径是什么？是否已有同义入口？
2. 双击、右键、拖拽或字段编辑的含义是否保持稳定？
3. 复杂度是否只在相关上下文出现？对象详情是否只隔离所属窗口，而非误锁其他独立工作窗口？
4. GUI、CLI、Agent 是否调用同一 Action 与业务规则？
5. 项目权威状态是否仍只有一份？预览和任务状态是否越界？
6. 插件是否只扩展语义，仍使用宿主交互与设计系统？
7. 并发、失败、取消或旧结果到达时，用户意图是否仍被保护？
8. 是否为尚未出现的需求引入了新的框架、继承层或第二套状态系统？

以下情况属于漂移信号：给重新生成同时加右键与悬浮按钮；拖 Asset 到 Item 时询问“引用还是替换”；插件创建自己的 Dialog；Agent 绕过执行器直接修改项目；前端与后端各维护一份可写项目；为了更换库而改变用户已形成的对象语法。

### 1.2 素材库入口调整

### 1.3 并行工作窗口与真实关系

- 关联需求：用户明确指出素材库弹出不能锁住主窗口，窗口应使用相同基类并能互相拖拽。
- 理解修正：此前把“独立窗口”一律当成“Modal 对象详情”是错误理解。独立工作窗口可以并行创作；对象详情仍隔离所属窗口的背景和旧层，两者并不冲突。
- 涉及原则：P01 保持默认工作区安静；P02 / P03 保留唯一入口及原关系语义；P04 将隔离限定在所属窗口；P05 / P07 由可信宿主验证跨窗口关系并提交同一 Action；P09 复用共同窗口宿主。
- 新规则：workspace 与 library 通过共同 `DesktopWindowHost` 组合 `BrowserWindow`，前端共用 `PixelWindowHost` 管理外观、窗口控制及生命周期，独立非模态运行；Viewer 右键 → 素材库的纯导航入口不变。库根无详情 frame，双击库对象只打开库自身的单 path 局部 Modal，不锁整个应用；详情 Esc 回库，根 Esc / close 关闭库。
- 关系及影响：库 Asset → 主 Timeline 放置/引用，主 Item → 库复用，均通过跨窗口 broker 执行既有 Action。桌面生产界面移除库内镜像 `relation-surface` 和可复用输出替代来源；不新增 GUI 命令，不改变项目 schema，不迁移已有项目，不调用付费生成。
- 浏览器载体与边界：开发版使用同源独立 popup（`?window=library`），复用同一 App / `PixelWindowHost`，不使用同 document 浮动库；平台最小化由浏览器系统负责。DataTransfer 只携带不透明会话 token，桌面由可信 IPC sender 与当前快照验证，浏览器开发版由同源窗口注册 hub 验证；目标仍使用自己的 `DragRegistry` 和 Action。
- 实现及验证状态：共同窗口宿主与可信跨窗口 broker 已接入，类型检查、96 项核心测试、12 项浏览器交互测试及原生桌面验证通过。覆盖非模态并行、局部详情隔离、双向放置/引用/复用、非法及重放 token、窗口控制、时间定位、持久化与文件导出。1.1 / 1.2 结果仅保留为历史证据。
