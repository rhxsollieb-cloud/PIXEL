发现以下 7 项问题，均已修正并复核；最终代码未发现剩余阻塞问题。项目权威状态和业务 Action 保持原有边界，未增加窗口间可写项目副本。

| 发现 | 修正 | 证据 |
| --- | --- | --- |
| 素材库也按主 Viewer 逻辑准备导出，触发 workspace 专属 IPC 拒绝 | `App` 导出 effect 排除 libraryMode | 原生回归覆盖库读取到零时刻输出时无导出错误；导出权限仍限定主 Viewer |
| 极短片段使用最小显示宽度，拖起偏移可能超过真实时长，原生 broker 拒绝 | 按真实 duration 钳制偏移，浏览器校验同一范围 | 浏览器和原生均覆盖 200ms 片段体拖回库；原生读取会话确认偏移为 200 tick |
| 浏览器源窗口创建取消计时器，却由另一 Window 清理同编号计时器 | 会话保存取消闭包，由创建它的 Window 清理 | 静态复核取消、单次消费与取代会话路径，浏览器双向拖拽回归通过 |
| 原生来源刷新或崩溃后 WebContents ID 不变，旧会话可能延续 | 主 frame 导航与 render-process-gone 均销毁来源会话 | 原生回归覆盖刷新后旧 token 不能解析或消费；崩溃清理钩子经代码复核 |
| 库内详情焦点环收集到 inert 背景的关闭控件 | 焦点候选及归属检查排除 inert、隐藏和禁用区域 | 浏览器验证库内详情 Shift+Tab / Tab 环绕至可交互的详情窗控 |
| 浏览器把主窗口根被详情隔离误当成整个接收窗口不可用 | 传输区分来源根作用域与存活接收窗口，合法目标继续由 DragRegistry / Navigator 校验 | 浏览器与原生均覆盖库 Asset 拖入主 Item 顶部详情引用区域 |
| 空 drop 可能借用尚在取消宽限中的活跃会话 | 仅带对象 MIME 的 hover 可以借用可信广播；实际 drop 必须读取其 token | 双端先投空 DataTransfer，确认项目不变且会话未消费，再投真实 token 成功 |
