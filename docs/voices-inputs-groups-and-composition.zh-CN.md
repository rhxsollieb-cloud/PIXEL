# 可发现的模型输入、素材分组与多轨预览

更新日期：2026-10-09。对应产品基线 1.6。产品规则以[设计哲学](design-philosophy.zh-CN.md)为准，契约与完成状态见[核心架构](core-architecture.zh-CN.md)。本文记录本轮对象、唯一入口、实现边界和评审证据。

## 1. 用户要求与基线取舍

用户明确要求模型上传入口可见，并修正最初的右键方案：“并不是右键，你需要再前端人性化的展示，不为了简洁而简洁，为了层次而层次。”同时要求素材自定义分组、时间线上下移动、按轨道层次叠加预览，以及有成熟包时优先复用。

因此 1.6 修正此前将“无按钮”解释为所有上下文都不能有操作控件的限制：默认主工作区继续围绕 Viewer 与 Timeline，模型详情、素材库和播放上下文直接展示完成当前任务所需的控件。唯一业务路径、后端权威状态和统一宿主仍保留。上传、声音来源及限制不能依赖用户猜测拖拽或右键。原始文件上传并引用与已有 Asset 建立引用分别有明确的前置条件和结果，不能靠换 Action 名称提供同义入口。

## 2. 对象与标准入口

| 对象 / 业务语义 | 唯一 GUI 路径 | 核心入口与结果 |
| --- | --- | --- |
| 模型输入说明 | Timeline 默认详情及 Item 详情中的输入说明 | 读取共享目录；说明文字字段、文件类型、当前模式的数量上下限，不写项目 |
| 原始文件导入并引用 | 支持引用的 Item 详情 → 上传参考文件 | `Workbench.importReferenceMedia()` → 内部 `media.referenceExternal`；校验、登记 Asset 和引用关系原子提交 |
| 已有 Asset 建立引用 | Asset → Item 引用区域拖拽 | `item.reference.add`；只建立关系，不上传文件 |
| Eleven v4 创建账号声纹 | Timeline 默认详情 → 选择音频、名称 → 克隆声纹 | 标准资源命令 `voice.clone` → `VoiceService.clone()`；返回账号资源回执，不编辑项目 |
| 选择声音 ID | 统一声音字段中的默认声音 / 我的克隆声纹 / 手填 ID | 仍由 `timeline.defaults` 或 `item.params` 提交字段；查询及翻页不写项目 |
| 素材分组管理 | 素材库分组导航旁的新建、重命名、删除表单 | `assetGroup.create` / `rename` / `remove`；删除组保留素材 |
| 素材归组 | 每个素材卡片下的分组字段 | `assetGroup.moveAsset`；移动或归为未分组 |
| 时间线上下重排 | 左侧名称旁的 ↕ 手柄，拖动或等价键盘操作 | `timeline.reorder`；只改变轨道顺序 |
| 多轨播放与定位 | Viewer 播放控件或时间尺播放指针 | 同一局部播放时钟，不提交项目 Action |
| 当前单一媒体输出拖出 | Viewer → 窗口外 | 原有文件准备与原生拖出票据；多输出叠加画面不冒充合成文件 |

名称区域仍单击进入时间线默认详情，手柄不会触发这条导航。片段本体移动、边缘调整和跨窗口 Asset 关系继续走原有统一 DragRegistry，不增加第二套对象 payload。排序包只负责手势计算，再提交共享 Action。

## 3. 模型声明与原子参考上传

`PluginFieldDeclaration.choicesSource` 声明远端字段选项来源；当前实现为 ElevenLabs 声音。`requiredTextFields`、`referenceKinds`、`referenceLimits` 与 `referenceMaxBytes` 来自同一模型目录。`src/reference-policy.ts` 的 `referenceLimit()` / `referenceMinimum()` / `referenceExceedsByteLimit()` 同时供 GUI 和后端输入校验使用，不在组件中按模型名称猜数量或文件大小。

Wan `firstFrame` 模式恰好需要一张图片，普通参考模式最多三张；Grok 最多三张图片。两者接受 PNG / JPEG / WebP，当前宿主的参考图片上限均为单文件 25 MiB，与 SDK 输入转换时的实际读取守卫一致；不是把通用媒体 HTTP 的 256 MiB 传输上限当作模型支持上限。当前三个 Eleven 音频模型不接受文件参考，详情显示简短说明，不呈现无效上传按钮。支持引用的 Item 即使尚无素材，仍显示参考区域、格式、字节上限、已用数量和上传按钮；达到上限时禁用上传。默认详情说明能力，但引用属于具体 Item，不放入默认配置。选择模式后的最少数量在生成前检查，草稿允许暂时未填完。

`POST /api/media-reference` 接收原始文件字节及当前项目、Item、请求编号与 revision；不接收任意本机路径。共同媒体入口校验真实内容、受控存储、插件能力、种类、重复、数量和字节限额，再在一个事务中登记 Asset 和引用。GUI 在发送超限文件前直接反馈，已有素材拖拽也按已知 `metadata.byteLength` 预检；后端仍重新检查，正式生成捕获同样拒绝已知超限引用。旧项目缺少字节元数据时不虚构验证结果，SDK 受控读取后按真实内容再次检查。失败不留下项目中的半个关系或空素材记录；迟到冲突可能留下受控但未关联的文件，清理策略仍独立。仅内部 handler 可登记已验证的文件，renderer 不能直接调用内部 Action 绕过检查。

## 4. 声纹属于账号资源

声纹既不是 Timeline 插件，也不是生成 Job 或 Asset。契约位于 `src/voice-contracts.ts`，共同执行流程位于 `VoiceService`，官方 SDK 适配位于 `ElevenLabsVoiceProvider`。Workbench 只做当前项目、v4 时间线、revision、音频内容和生命周期的可信接线。

创建接受一个不超过 25 MiB 的 MP3 / WAV 文件，先按真实媒体内容探测。可信入口将 `audio/x-wav` / `audio/wave` 规范化为 `audio/wav`，同一 WAV 内容不会因为 MIME 别名而被拒绝或重复创建。选择文件仅建立本地表单草稿；点击“克隆声纹”才调用官方 `voices.ivc.create`。返回结果保留 `voiceId`、名称、来源和 `ready` / `verificationRequired` / `unavailable` 状态。克隆成功不自动修改默认音色、已有片段、引用、输出或生成 token；用户随后在声音字段中选择，默认值变更仍保留旧片段，显式刷新规则不变。

声音查询使用官方 `voices.search`：默认声音与自己的 IVC / PVC 分开筛选，支持搜索及继续查询。核心默认每页 5 项，上限 20，GUI 显式请求每页 20 项；供应商首屏溢出留在后端分页缓存，不丢弃后续资源。游标绑定凭证作用域和筛选条件。待验证、被限制或尚未就绪的选项禁用，并展示可理解的状态；当前手填 ID 不因换分类或搜索结果缺失而被清空。没有供应商限制字段时，不凭空把声音标成不可用。

`voice.clone` 是具有外部副作用的资源命令，不能把它放进可撤销项目编辑事务。独立 `voice-operations` ledger 先持久化 attempted，再发远端创建；requestId 绑定文件内容、名称、项目、时间线、初始 revision 与凭证作用域。相同内容的成功回执可在后续 revision 或重启后重放，不再创建；不同内容复用 ID 被拒绝。当前作用域由 API key 哈希标识，更换密钥后不能沿用原回执作用域。ledger 不保存原始音频或密钥，不进入 ProjectDocument 或 undo 历史。

断线、超时或关闭后的结果可能不确定，记录 `OUTCOME_UNKNOWN`，同一请求不会自动重提，提示查询自己的声音或到 ElevenLabs 核对。迟到成功不覆盖已记录的 unknown，也不回填当前字段。SDK 创建禁用自动重试，服务关闭先取消，再等待终态记录持久化；符号链接 / junction 不得把账本读写引向受控目录之外。

IVC 创建响应可要求验证；当前没有接入 IVC 验证流程，用户在 ElevenLabs 完成后重新查询。PVC 的验证码接口不能当作 IVC 验证接口使用。官方接口说明见 [IVC 创建](https://elevenlabs.io/docs/api-reference/voices/ivc/create)及[声音查询](https://elevenlabs.io/docs/api-reference/voices/search)。后端继续从应用 `.env` 读取配置，凭证不返回浏览器，也不读取拖入项目中的配置文件。

## 5. 素材组与轨道顺序

`ProjectDocument.assetGroups?` 保存 `{ id, title, assetIds }` 映射。名称去首尾空格后为 1–80 字符；组键与 ID 一致，成员必须存在，一个素材最多属于一个组，不允许组内重复。旧版项目缺少该字段仍可打开，不为只读查询自动迁移。素材删除清理组成员；分组删除只删除组。分组不改变媒体文件、已有 Item 输出或引用。

分组列表与成员由各窗口读取同一后端快照；筛选、当前分组和新名称草稿只属于窗口局部状态。分组 ID 与“全部 / 未分组”导航值隔离，合法外部项目 ID 不会与宿主虚拟导航冲突。

`ProjectDocument.timelineOrder?` 是完整、不重复、只含当前项目轨道的 ID 列表。旧文件缺少时，`orderedTimelineIds()` 按原对象登记顺序投影，不写项目。重排通过 `timeline.reorder({ timelineId, beforeTimelineId? })` 提交；没有 before 表示移到底部。创建、删除和系统文件放置新轨道共同维护已显式保存的顺序。当前状态和每份持久化历史都检查这些不变量。

上移 / 下移不改变 Item 的正文、时间、默认值、输出或请求 token。排序采用固定版本的 `@dnd-kit/core`、`@dnd-kit/sortable` 和 `@dnd-kit/utilities`，使用纵向排序、独立手柄和键盘 Sensor。手柄事件不能阻断库在 document 上监听的键盘结束事件，也不能冒泡触发名称详情。

## 6. 预览复用成熟播放包

主 Viewer 由 `@remotion/player` 与 `remotion` 4.0.534 组成。两包保持同版本。`web/composition.ts` 将后端只读快照转换为播放计划，不维护第二份可写项目；`CompositionPreview` 只负责播放、缓冲和局部时间反馈。包选择及 API 见 [Remotion Player](https://www.remotion.dev/docs/player)、[dnd-kit Sortable](https://dndkit.com/legacy/presets/sortable/overview/)。

当前画布固定 1280×720、16:9、60fps。按轨道由上到下确定 z-index：上层轨道在前景，下层从透明部分或未覆盖区域透出；视频和图片保持比例，透明图片保留 alpha。所有真实输出参与预览，选中笔记不会遮蔽画面，文本参考和未生成草稿不产生画面层。音频与视频自带声音按各自片段时间并发播放。

片段使用半开区间 `[startTick, startTick + durationTicks)`，各轨道整数 tick 按其 ticksPerSecond 投影到播放帧。源偏移映射到 trimBefore，不把媒体时间误当项目时间；帧舍入不改写持久化 tick。预览末尾保留一个空帧，定位到结束或之后不会停留在最后输出。60fps 是预览精度，不是把项目时间存储改成 60Hz。

Player 控件和时间尺通过同一 playhead 双向同步，外部 seek 与 frameupdate 有回写守卫；被动播放反馈继续更新局部时间，用户定位仍受所属窗口的交互隔离。刷新项目数据不靠重新挂载 Player 丢失播放节点。共享音频标签池设为 0，使用各媒体自己的标签，增加并发片段不受默认池容量限制。控件字体沿用统一 Fusion Pixel 12px。Viewer 元信息和双击进入当前最上层画面 Item；只有音频时取最上层音频，空白时不进入曾选片段。

这次完成多轨实时预览，尚未生成合成视频文件。Viewer 只有一个有效媒体输出时继续允许准备并拖出该文件；有多个有效输出时不提供伪合成导出。完整合成导出、项目画布设置、音量自动化、严格源末端裁切和完整 undo/redo 仍是后续工作。

Remotion 的许可不是 MIT：个人、非营利组织及雇员不超过三人的营利组织可依免费条款使用；不符合这些条件的组织需要公司许可，具体条款及对衍生品再销售的限制见[官方许可](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md)。仓库不伪造许可确认。其余依赖的实际版本与许可随 lockfile / 安装包保留。

## 7. 长菜单与共同宿主

右键继续承载已登记的离散命令，但声纹上传、文件参考上传和分组管理不再被藏到右键里。长菜单由 PixelContextMenu 共用 `layoutMenuColumns()`：测量完整行的实际高度，按可用视口高度分栏，保留来源顺序和完整标签；总列宽超出窗口时允许水平滚动，单行过高时保留竖向滚动。位置随边界和窗口变化校正。上下方向键在列内移动、左右跨列、跳过禁用项，Esc 返回来源焦点。长列表规则由宿主统一处理，不让插件实现自己的菜单布局。

## 8. 设计哲学第 10 节评审

1. **对象与唯一入口：** 第 2 节逐项登记。Account Voice 与 Project Asset / Item 分开；原始文件导入并引用与已有 Asset 引用前置条件、结果不同，不登记同义右键上传。
2. **手势语义：** 名称单击详情、对象双击详情、片段关系拖拽保持原含义；排序手柄是独立来源。可见上下文命令来自用户明确纠正，已同步 1.6 决策。
3. **上下文与隔离：** 输入控件只在模型详情，分组只在素材库，播放只在 Viewer；详情仍只隔离所属窗口，未新增导航层或应用级模态树。
4. **共同执行：** 项目修改走共同 Action；账号副作用走共享 VoiceService 资源命令；GUI / 后续可信 Agent 可复用同一契约。正式 Agent 编辑适配器没有被宣称完成。
5. **权威状态：** 分组和顺序只保存于后端项目；分页缓存、表单草稿、选中、筛选与播放时钟都是局部或服务状态。克隆结果不隐式写项目。
6. **插件边界：** 通过目录声明字段来源、文本要求、参考类型及条件 min/max，宿主渲染；新模型不需要继承视频 Item 或复制上传组件。
7. **失败与旧结果：** 项目 revision / 请求幂等 / 生成 token 守卫继续有效；参考上传原子提交；声纹 attempt 先落盘、不确定结果不重投，关闭与迟到结果不会改默认。
8. **复杂度依据：** 使用现有排序和播放包应对明确需求，新增纯数据投影与组合组件，不引入通用渲染继承树、第二份项目状态或未要求的可配置画布系统。
