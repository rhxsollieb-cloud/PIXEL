# Pixel 本地桌面与像素界面

当前基线为 1.5，已增加纯文本参考轴和普通视频 / 音频 / 图片轴，全部复用 Timeline 基类与像素组件。空白区右键建轨时选择类型；文本轨右键创建片段、双击编辑，普通媒体文件可直接拖入匹配轨道或空白区自动建轨放置。本地轨不启动模型。外部 Agent 的只读文本命令、统一拖拽及扩展契约见[本地时间线与扩展边界](local-timelines-and-extension.zh-CN.md)。

## 运行

Windows 可直接双击仓库根目录的[启动Pixel.cmd](../启动Pixel.cmd)。它自动切换到项目目录，检查 Node.js、同步锁定依赖（包含开发依赖），构建最新源码并启动桌面窗口；启动失败时保留命令窗口显示原因。源码改动后再次双击即可加载新构建。

```sh
npm install
npm run desktop
```

`desktop` 先构建界面与后端，然后启动 Electron。已构建时可以使用 `npm run desktop:launch`。`npm run package:win` 生成 `release/Pixel-0.1.0-Windows.exe`，可直接运行，无需安装 Node.js。`npm run dev` 保留浏览器开发入口。

当前保留源码开发模式，不重新打包。持续调整前端使用 `npm run dev`，浏览器界面由 Vite 热更新；检验独立原生窗口时使用 `npm run desktop`。原生版读取本地构建产物，源码变更后关闭窗口并重新运行该命令；`desktop:launch` 只复用上次构建，不宣称原生窗口已实现热更新。

CSS 和普通视图组件可热更新；`App` 组合根修改时整页重新加载，以重新创建已销毁的投影、导航与交互服务。已通过刷新后继续进入详情、返回及项目快照保持一致的运行验证；未提交的界面草稿和导航状态在整页刷新时重置。

桌面首次使用默认目录 `%APPDATA%/Pixel/project`。将 Pixel `project.json` 或已有项目目录拖入主窗口，在原位置打开；将真正的空文件夹拖入，在该目录创建并打开空项目，标题采用文件夹名称。普通非空目录、未知或空文件明确拒绝，不把媒体目录当项目合并。成功打开的位置由宿主记忆，关闭及再次启动继续该项目；原位置不可用时回退默认目录。新项目的时间线、片段与素材均为空，已有项目完整保留。

开发版模型配置仍读取仓库 `.env`；打包版读取 `%APPDATA%/Pixel/.env`。拖入的项目目录不提供模型凭证，也不能用其中的 `.env` 覆盖应用配置。配置模板见 `.env.example`。密钥只进入后端，界面仅接收必要配置状态。未配置时仍可编辑、导入与预览已有素材。浏览器开发版不能可靠取得本机目录路径，主窗口拖入文件时明确提示使用桌面版；素材库的媒体上传继续可用。打开规则及错误边界见[项目打开与系统拖拽](project-open-and-system-drag.zh-CN.md)。

## 视觉与交互

视觉保留暖白底、深蓝字、有限强调色、本地 Fusion Pixel 12px 字体及直角窗口。像素用于统一栅格、字体、间距与状态，区域以留白和细分隔线组织；字段使用淡底与底线，避免卡片厚边框与硬阴影。默认主界面只有上方 Viewer 和下方 Timeline，另保留当前作品标题与必要原生窗口控件。空 Viewer 显示简短空状态，不展示示例星空或人造波形；版本、色板、手势教程、素材筛选、配置提示与调试 revision 不再常驻。

作品、片段和素材通过双击进入详情；时间轴左侧名称区域按 1.4 单击进入默认配置，Enter 为同一入口的键盘表达，移除旧双击入口与片段详情内的同义跳转。右键执行当前对象命令，拖拽建立已登记关系。素材库的唯一进入路径是主 Viewer 右键 → 素材库，空预览或已有输出均可。该菜单项仍是 P03 的局部导航例外，不提交业务 Action；1.3 将库明确为非模态工作窗口，打开库不能锁住主窗口。作品标题双击只进入项目详情，没有素材库第二入口。Timeline 工作区空白处右键 → 新建时间线 → 选择类型只创建空 Timeline，不附送首个草稿。已有生成 Timeline 时间位置右键 → 新建生成草稿，显式创建尚无输出的 Item；Asset 拖到时间位置则创建关联已有素材的 Item。两种能力分别表达生成新内容与放置已有内容，不能增加互换的按钮或拖拽入口。保存反馈、失败及真实任务进度仅在相关状态出现，不以常驻提示或业务工具栏代替对象语法。

默认配置字段完成编辑后，经共享 Action 保存；已有片段保留自己的参数及生成设置，新片段采用当前默认值。时间轴左侧右键 → 刷新时间轴默认配置才把默认值应用到已有片段，保留正文、位置及引用；生成输入实际改变时解除旧生成输出关联，已放置的真实媒体继续保留。默认配置不是批量正文编辑，刷新不会启动收费生成。语音详情和默认配置增加上下文模式、裁尾及余量参数，继续使用现有像素字段控件和单 Modal 嵌套导航；细节见[默认配置与语音连续性升级](timeline-defaults-and-speech.zh-CN.md)。

1.3 纠正此前把独立素材工作窗口一律当作 Modal 对象详情的错误理解。workspace 与 library 是非模态并行工作窗口，桌面通过共同 `DesktopWindowHost` 组合 `BrowserWindow` 管理生命周期，前端共用 `PixelWindowHost` 的视觉与窗口控制。对象详情仍保留每个所属工作窗口自己的单一 `PixelModalHost` 和导航 path，只隔离该窗口的背景及旧详情层，不锁整个应用；另一个工作窗口仍可交互。

Viewer 菜单直接创建或聚焦素材库工作窗口。库根是素材列表，没有导航 frame；库内双击对象在库 document 内打开局部 ModalHost，只隔离库自身。Esc 退出详情返回库，库根 Esc / close 关闭库窗口。浏览器开发版使用同源独立 popup（`?window=library`），复用同一 App / `PixelWindowHost`；不使用同 document 浮动库，平台最小化由浏览器系统负责。

关系直接在真实工作窗口间建立：库 Asset → 主 Timeline 时间位置放置，库 Asset → Item 引用区建立引用，主 Item → 库保存为可复用素材。桌面生产界面移除库内镜像 `relation-surface` 与可复用输出替代来源，不新增业务命令。DataTransfer 只携带不透明 session token；桌面由可信 sender 与当前项目快照验证，浏览器开发版由同源窗口注册 hub 验证。目标仍经自身 `DragRegistry` 的既有角色路由提交 Action。无图像引用能力的模型不显示引用区；支持引用时只在已有关系或合法拖拽上下文呈现，Wan 首帧模式的有效上限为一张。

各工作窗口读取同一个后端，通过同一 Action 协议提交编辑，通过事件刷新只读投影。窗口操作及受控 broker 走窄 preload IPC，不授予 renderer Node.js 或文件系统访问。桌面后端绑定随机 loopback 端口并验证会话 Cookie；项目身份和权限仍由后端注入。共同窗口宿主及跨窗口会话已实现，1.3 的浏览器与原生运行验证均通过。

系统项目 drop 只在主工作窗口根打开项目；媒体 drop 在素材库登记可复用资产，在普通媒体 Timeline 或空白区则原子导入并放置，经过同一 DragRegistry 的确定路由。打开项目前完成目标校验；目标有未处理 outbox 或仍排队、运行、取消中的生成任务时拒绝外部打开，防止文件打开隐式启动模型。切换时撤销旧对象会话和导出票据、关闭详情及库，将主窗口导航至新端口及 Cookie 的 origin；导航失败恢复旧项目，成功后关闭旧后端并保存中断状态。投影、详情、字段草稿、选择、播放指针及拖拽预览重新创建；旧窗口和旧请求不能继续编辑新项目。已中断的远端任务仍由对象右键显式恢复。

播放指针是当前窗口的时间定位状态。用户在时间标尺点击定位，或拖动指针手柄连续查看当前位置；方向键、Home / End 是同一定位控件的键盘表达。当前位置驱动实际片段预览，音视频按片段内时间与素材偏移定位，没有输出时显示中性空状态。定位不提交 Action，不修改片段位置，不写入项目或启动生成；当前不代表已经实现多轨混音与整条时间线合成。

工作窗口的标题栏及控件使用共同 `PixelWindowHost` 视觉；控件及子元素使用 `no-drag`，防止原生窗口拖动区域截获点击。原生工作窗口应有正常最小化、恢复与关闭生命周期，素材库这些操作不禁用主窗口或改变其最大化状态。对象详情只保持所属窗口的局部隔离，不把工作窗口最小化和详情导航混为同一状态。

Viewer 提前准备当前媒体的导出 ticket，准备完成才允许拖动。原生拖出只消费宿主验证的 ticket，以真实媒体文件调用 Electron `startDrag`；不接受 renderer 提供任意文件路径。ticket 绑定窗口、限时且单次消费，拖出后重新准备以支持再次拖动。

## 设计哲学评审

- 对象及唯一入口：仍为现有 Project、Timeline、Item、Asset；Timeline 左侧单击唯一进入默认配置，右键唯一刷新，属于用户要求的 P03 局部导航例外。素材库唯一入口仍是主 Viewer 右键，项目详情没有第二入口。模型及生成草稿保持已有右键路径；素材放置、引用与复用改由真实窗口关系呈现，仍使用原来的 Action。
- 渐进披露与隔离：不增加常驻参数面板；库为独立非模态工作窗口，主窗口继续工作。对象详情只显示所属窗口的顶部导航层并隔离该窗口，不全应用锁定，也不解除局部详情背景隔离。
- 状态与业务边界：项目仅由后端维护；新项目与新 Timeline 不预置创作内容，既有项目保持完整。子窗口具有自己的导航及字段草稿，不复制可写项目状态；字段及模型参数由宿主统一渲染。
- 桌面边界：Electron 是本地宿主；GUI HTTP Action 进入同一 `Workbench` / `ActionExecutor`。正式项目 CLI / Agent 适配器仍待接线；诊断 CLI 仅复用模型执行内核，不等于当前项目的 Action 入口。
- 项目及系统拖拽：既有项目文件和空文件夹共用主窗口根的唯一进入路径，由容器内容决定打开或初始化，不增加按钮、菜单或合并选择。库的媒体导入、内部对象关系与 Viewer 当前媒体的原生拖出继续使用各自边界；项目切换先隔离旧会话，不能靠客户端改写 projectId 移接请求。

## 验证与边界

`npm run typecheck`、`npm test`、`npm run test:ui`、`npm run test:desktop` 分别验证类型、核心业务、浏览器手势及原生窗口。测试不调用付费生成。

1.1 的 91 项核心测试及 1.2 的类型检查、12 项浏览器交互测试和原生桌面测试作为历史证据保留在[哲学对齐记录](philosophy-alignment.zh-CN.md)。其中“库打开后主窗口禁用”和库内镜像关系面属于已被 1.3 纠正的旧实现，不能作为新窗口模型通过证据。1.3 的类型检查、96 项核心测试、12 项浏览器交互测试及原生桌面验证通过，覆盖共同窗口宿主、非模态工作窗口、双向对象拖拽及各窗口局部详情隔离。原生跨窗口测试用真实鼠标拖起来源对象，再以 Chromium drag 事件向另一原生窗口投放；未自动化 Windows 屏幕坐标间的完整系统鼠标拖动。本轮不迁移项目、不调用付费生成、不增加常驻控件，继续源码开发模式，不重新打包。

跨窗口对象 broker 已实现并通过会话、来源与目标校验、过期/主动取消、删除/关闭、非法及重复 token 回归。项目文件及目录拖入打开已完成；1.5 的类型检查、152 项核心测试、19 项浏览器交互测试和原生验证通过，覆盖文本编辑、普通媒体放置及真实时长、只读文本读取、主窗口 Files 入口、素材库拒绝目录、动态项目 ID，以及原有窗口间双向对象关系和重启恢复。系统输入的原生自动化采用 Chromium / CDP 投放真实磁盘 File，Viewer 导出使用真实鼠标触发原生 startDrag；这不等于已自动化 Windows Explorer 与外部应用之间完整屏幕坐标拖拽。最终记录见[本地时间线与扩展边界](local-timelines-and-extension.zh-CN.md)。

完整撤销重做、插件版本迁移与缺失插件占位、正式项目 CLI / Agent 编辑适配器、共享 Action 能力查询与完整时间线合成导出仍待实现；只读文本 CLI 已完成。原生文件拖出支持 Viewer 当前的单个媒体文件，尚不进行整条作品的合成；该文件导出边界与窗口间对象关系 broker 不混用。本轮继续源码开发，Windows 可执行文件未重新打包；旧版本安装包不会因此自动更新。
