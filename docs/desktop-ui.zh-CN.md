# Pixel 本地桌面与像素界面

当前基线为 1.7。模型详情直接说明输入能力，v4 默认详情提供声纹上传与选择，生成视频详情可上传人工或网页生成的成片；素材库可管理自定义组，时间线可上下排序，Viewer 按上层覆盖下层播放叠加结果。轨道占满窗口时仍能从已有轨道或片段右键创建时间线，普通媒体轨可右键上传并添加。必要控件在相关上下文中直接展示，不为简洁增加寻找或导航成本；入口由共同宿主管理，普通媒体选择器与拖入的同义例外按用户明确要求记录。产品取舍见[设计哲学](design-philosophy.zh-CN.md)，当前契约见[共享资源与人工输出](shared-resources-and-manual-output.zh-CN.md)，1.6 记录见[声纹、输入、分组与叠加预览](voices-inputs-groups-and-composition.zh-CN.md)。

1.5 的纯文本参考轴和普通视频 / 音频 / 图片轴继续复用 Timeline 基类与像素组件。主时间线各对象上下文共用同一右键建轨类型菜单；文本轨右键创建片段、双击编辑，普通媒体文件可直接拖入匹配轨道或空白区自动建轨放置，也可在已有普通媒体轨右键“上传并添加”。本地轨不启动模型。外部 Agent 的只读文本命令、统一拖拽及扩展契约见[本地时间线与扩展边界](local-timelines-and-extension.zh-CN.md)。

## 运行

Windows 可直接双击仓库根目录的[启动Pixel.cmd](../启动Pixel.cmd)。它自动切换到项目目录，检查 Node.js、同步锁定依赖（包含开发依赖），构建最新源码并启动桌面窗口；启动失败时保留命令窗口显示原因。源码改动后再次双击即可加载新构建。

```sh
npm install
npm run desktop
```

`desktop` 先构建界面与后端，然后启动 Electron。已构建时可以使用 `npm run desktop:launch`。`npm run package:win` 生成 `release/Pixel-0.1.0-Windows.exe`，可直接运行，无需安装 Node.js。`npm run dev` 保留浏览器开发入口。

当前保留源码开发模式，不重新打包。持续调整前端使用 `npm run dev`，浏览器界面由 Vite 热更新；检验独立原生窗口时使用 `npm run desktop`。原生版读取本地构建产物，源码变更后关闭窗口并重新运行该命令；`desktop:launch` 只复用上次构建，不宣称原生窗口已实现热更新。

CSS 和普通视图组件可热更新；`App` 组合根修改时整页重新加载，以重新创建已销毁的投影、导航与交互服务。已通过刷新后继续进入详情、返回及项目快照保持一致的运行验证；未提交的界面草稿和导航状态在整页刷新时重置。

桌面首次使用默认目录 `%APPDATA%/Pixel/project`。将 Pixel `project.json` 或已有项目目录拖入主窗口，在原位置打开；将真正的空文件夹拖入，在该目录创建并打开空项目，标题采用文件夹名称。普通非空目录、未知或空文件明确拒绝，不把媒体目录当项目合并。成功打开的位置由宿主记忆，关闭及再次启动继续该项目；原位置不可用时回退默认目录。新项目的时间线、片段与素材均为空，已有项目完整保留。

开发版模型和 Seafile 配置读取仓库 `.env`；打包版读取 `%APPDATA%/Pixel/.env`。拖入的项目目录不提供凭证，也不能用其中的 `.env` 覆盖应用配置。配置模板见 [`.env.example`](../.env.example)。凭证只进入后端，界面仅接收必要配置状态。生产资源全部保存至 Seafile，未配置或不可达时明确失败，不回退本地媒体存储；缺少模型密钥时可在资源服务可用的前提下编辑、导入与预览，收费生成仍受供应商配置检查。项目 JSON、历史、生成任务和声纹账本继续保存在项目目录，资源共享不等于多人同时编辑项目。旧资源迁移保留句柄及原文件，预览通过后端代理读取；原生导出只准备退出时清理的会话临时副本。浏览器开发版不能可靠取得本机项目位置，项目文件或目录打开会提示使用桌面版；普通媒体拖入放置、素材库导入及详情文件选择仍可使用。资源契约见[共享资源与人工输出](shared-resources-and-manual-output.zh-CN.md)，打开规则及错误边界见[项目打开与系统拖拽](project-open-and-system-drag.zh-CN.md)。

## 视觉与交互

视觉保留暖白底、深蓝字、有限强调色、本地 Fusion Pixel 12px 字体及直角窗口。像素用于统一栅格、字体、间距与状态，区域以留白和细分隔线组织；字段使用淡底与底线，避免卡片厚边框与硬阴影。默认主界面只有上方 Viewer 和下方 Timeline，另保留当前作品标题与必要原生窗口控件；Timeline 显示上下手柄，有作品输出的 Viewer 显示播放控件。空 Viewer 显示简短空状态，不展示示例星空或人造波形；版本、色板、手势教程、素材筛选、配置提示与调试 revision 不再常驻。模型输入按钮和资源分组直接显示在对应详情或工作窗口，沿用统一字号、焦点和禁用状态。

作品、片段和素材通过双击进入详情；时间轴左侧名称区域按 1.4 单击进入默认配置，Enter 为同一入口的键盘表达，移除旧双击入口与片段详情内的同义跳转。右键提供已登记的对象命令，拖拽建立已登记关系；模型参考、声纹、人工生成结果及分组使用可见上下文控件，不另藏进右键。素材库的唯一进入路径是主 Viewer 右键 → 素材库，空预览或已有输出均可。该菜单项仍是 P03 的局部导航例外，不提交业务 Action；1.3 将库明确为非模态工作窗口，打开库不能锁住主窗口。作品标题双击只进入项目详情，没有素材库第二入口。主 Timeline 空白处、名称、时间位置和 Item 右键共用“新建时间线 → 选择类型”，只创建空 Timeline，不附送首个草稿，也不绕过详情隔离。已有生成 Timeline 时间位置右键 → 新建生成草稿，显式创建尚无输出的 Item；Asset 拖到时间位置则创建关联已有素材的 Item。普通媒体轨右键的“上传并添加”只选取真实媒体并在指定位置放置，复用文件拖入的路由及 `media.placeExternal`，这是用户明确要求的 P02 例外，不改变生成草稿或引用语义。保存反馈、失败及真实任务进度仅在相关状态出现，不以常驻提示或全局业务工具栏代替对象语法。

长右键菜单按可用宽高分栏摆放；屏幕过窄或不足以完整容纳时回退为滚动区域。键盘方向键、Home / End、Enter 选择与 Esc 返回继续有效，不能为避免超出屏幕而删除相关命令。

默认配置字段完成编辑后，经共享 Action 保存；已有片段保留自己的参数及生成设置，新片段采用当前默认值。时间轴左侧右键 → 刷新时间轴默认配置才把默认值应用到已有片段，保留正文、位置及引用；生成输入实际改变时解除旧生成输出关联，已放置及人工上传的真实媒体继续保留。默认配置不是批量正文编辑，刷新不会启动收费生成。语音详情和默认配置增加上下文模式、裁尾及余量参数，继续使用现有像素字段控件和单 Modal 嵌套导航；细节见[默认配置与语音连续性升级](timeline-defaults-and-speech.zh-CN.md)。

Eleven v4 默认详情直接显示“克隆自己的声音”：选择单个 MP3 / WAV 音频（25 MB 以内）、查看文件并确认声纹名称，再点击“克隆声纹”。选文件和输入名称只保存在当前界面，不立即调用供应商。提交期间控件禁用，重复点击不会再次提交；返回声音 ID 与可用、待验证或不可用状态。创建声纹不自动设置默认声音，也不修改已有片段。关闭详情后的晚到结果不重新打开窗口或提交声音字段；不确定的供应商结果提示核对，不能自动重建。

“声音 ID”是一个字段，支持默认声音、自己的克隆声纹、搜索分页与手填 ID。切换目录或搜索不修改字段；用户明确选择或提交 ID 才走现有 `timeline.defaults` / `item.params`。目录中待验证或不可用的声音禁用，当前不在目录中的 ID 仍保留。更改时间线声音只影响新片段，已有片段仍等待左侧右键的显式刷新。前端不读取密钥或调用 SDK，声纹由可信后端账户服务管理，不生成媒体输出或写入项目撤销历史。

1.3 纠正此前把独立素材工作窗口一律当作 Modal 对象详情的错误理解。workspace 与 library 是非模态并行工作窗口，桌面通过共同 `DesktopWindowHost` 组合 `BrowserWindow` 管理生命周期，前端共用 `PixelWindowHost` 的视觉与窗口控制。对象详情仍保留每个所属工作窗口自己的单一 `PixelModalHost` 和导航 path，只隔离该窗口的背景及旧详情层，不锁整个应用；另一个工作窗口仍可交互。

Viewer 菜单直接创建或聚焦素材库工作窗口。库根是素材列表，没有导航 frame；库内双击对象在库 document 内打开局部 ModalHost，只隔离库自身。Esc 退出详情返回库，库根 Esc / close 关闭库窗口。浏览器开发版使用同源独立 popup（`?window=library`），复用同一 App / `PixelWindowHost`；不使用同 document 浮动库，平台最小化由浏览器系统负责。

库内直接显示“全部素材”“未分组”和自定义组导航，并提供名称输入及新建、重命名、删除组操作。每个素材卡片有同一分组字段，可移到一个自定义组或回到未分组；删除组保留素材和已有引用。分组名称及成员通过 `assetGroup.*` Action 持久化，当前查看的组是窗口状态。分组不移动 Seafile 资源文件，也不为素材增加第二套对象身份；卡片继续使用原来的双击详情和跨窗口拖拽。

关系直接在真实工作窗口间建立：库 Asset → 主 Timeline 时间位置放置，库 Asset → Item 引用区建立引用，主 Item → 库保存为可复用素材。桌面生产界面移除库内镜像 `relation-surface` 与可复用输出替代来源，不为已有 Asset 引用新增另一条 GUI 路径。DataTransfer 只携带不透明 session token；桌面由可信 sender 与当前项目快照验证，浏览器开发版由同源窗口注册 hub 验证。目标仍经自身 `DragRegistry` 的既有角色路由提交 Action。

生成 Item 详情始终说明文字输入、可接受的参考文件格式、当前已用数量及参数决定的最小 / 最大值。支持引用时，即使数量为零也显示引用区及“上传参考图片”等对应按钮；满额禁用并说明。原始 File 通过该按钮进入 `media.referenceExternal`，后端把导入与引用共同原子提交，失败不留下项目素材记录；它与已有 Asset 拖拽的前置条件和结果不同，不是重复入口。未支持文件参考的模型只显示“不接受文件参考”，没有假上传按钮或引用管理区。默认详情说明相同输入规则，具体片段引用不作为批量默认值。Wan 首帧需要且最多一张参考图片，数量由共享声明决定；切换参数时提示同步更新。主时间线的引用提示仍可按已有关系或合法对象拖拽显示。

声明 `manualOutput` 的生成视频 Item 详情直接显示“上传生成结果”，来源可选人工上传或外部网页生成。网页流程是用户在相应服务完成生成、下载 MP4，再通过同一个控件上传；Pixel 不替用户操作网页，也不调用生成 API。上传每次一个 MP4，最多 256 MiB，后端检查真实视频与时长。成功挂载到原片段并保留模型、提示词、设置和位置，取消旧任务且防止旧结果覆盖；参数修改或默认刷新保留人工输出。视频较短时缩短片段，较长时保留原区间，偏移重置为 0，可在时间线上调整边缘使用更多内容；来源及源时长在详情中显示。这个区块和“上传参考”区块分别表达输出与输入，不能混用。

各工作窗口读取同一个后端，通过同一 Action 协议提交编辑，通过事件刷新只读投影。窗口操作及受控 broker 走窄 preload IPC，不授予 renderer Node.js 或文件系统访问。桌面后端绑定随机 loopback 端口并验证会话 Cookie；项目身份和权限仍由后端注入。共同窗口宿主及跨窗口会话已实现，1.3 的浏览器与原生运行验证均通过。

系统项目 drop 只在主工作窗口根打开项目；媒体 drop 在素材库登记可复用资产，在普通媒体 Timeline 或空白区则原子导入并放置，经过同一 DragRegistry 的确定路由。打开项目前完成目标校验；目标有未处理 outbox 或仍排队、运行、取消中的生成任务时拒绝外部打开，防止文件打开隐式启动模型。切换时撤销旧对象会话和导出票据、关闭详情及库，将主窗口导航至新端口及 Cookie 的 origin；导航失败恢复旧项目，成功后关闭旧后端并保存中断状态。投影、详情、字段草稿、选择、播放指针及拖拽预览重新创建；旧窗口和旧请求不能继续编辑新项目。已中断的远端任务仍由对象右键显式恢复。

时间线名称旁的可见 ↕ 手柄使用 dnd-kit 上下排序，排序预览结束后通过 `timeline.reorder` 保存项目轨道顺序。焦点进入同一手柄后，可用空格启动、方向键移动、空格完成或 Esc 取消。手柄不触发名称单击配置入口，也不改变 Item 的时间位置、长度或素材身份；排序属于项目编辑，不能只修改 DOM 展示顺序。

播放指针是当前窗口的时间定位状态。用户在时间标尺点击定位，或拖动指针手柄连续查看当前位置；方向键、Home / End 是同一定位控件的键盘表达。主 Viewer 使用 Remotion / Player 读取现有项目投影，显示可见播放控件，并与时间线指针使用同一播放位置。上方轨道的图像 / 视频覆盖下方轨道，透明部分保留下层，音频按生效区间同时播放；音视频尊重片段起止与素材偏移，纯文本和未生成草稿不成为媒体输出。无生效输出时显示中性空状态。播放与定位不提交 Action，不修改片段位置，不写入项目或启动生成。该能力是多轨叠加预览，整条作品的合成文件导出仍未实现。

工作窗口的标题栏及控件使用共同 `PixelWindowHost` 视觉；控件及子元素使用 `no-drag`，防止原生窗口拖动区域截获点击。原生工作窗口应有正常最小化、恢复与关闭生命周期，素材库这些操作不禁用主窗口或改变其最大化状态。对象详情只保持所属窗口的局部隔离，不把工作窗口最小化和详情导航混为同一状态。

Viewer 在当前恰好一个媒体输出时提前从 Seafile 读取并校验该媒体，准备会话临时文件和导出 ticket，完成后才允许拖动。多个输出同时生效时禁用拖出，不能把其中一个源文件当作合成作品导出；不增加生成或合成导出按钮。原生拖出只消费宿主验证的 ticket，以真实媒体临时文件调用 Electron `startDrag`；不接受 renderer 提供任意文件路径，临时副本不成为资源存储，关闭会话时清理。ticket 绑定窗口、限时且单次消费，拖出后重新准备以支持再次拖动。Viewer 元信息和双击详情对应当前最上层的画面 Item；没有画面时对应最上层音频，没有生效输出时不进入曾选片段。片段选择不改写预览的层次，预览不会创建新输出对象。

## 1.6 设计哲学评审记录

- 对象及唯一入口：现有 Project、Timeline、Item、Asset 增加项目中的资源分组和轨道顺序，以及后端账户声纹资源。Timeline 名称单击配置、左侧右键刷新和 Viewer 右键素材库保持唯一。声纹仅在 v4 默认详情可见表单创建；声音目录、搜索和手填仍提交同一字段。已有 Asset 引用保持拖拽；原始 File 导入并引用仅用 Item 详情上传按钮，两者来源和原子结果不同。组管理、Asset 分组字段及排序手柄各自有固定业务入口。
- 渐进披露与隔离：当前模型的必要输入和上传能力直接显示，不为简洁增加详情层；不展开全局参数面板。库仍为独立非模态工作窗口，组导航与管理表单在库内可见。对象详情只显示所属窗口的顶部导航层并隔离该窗口，不全应用锁定，也不解除局部详情背景隔离。
- 状态与业务边界：项目仅由后端维护；分组及轨道顺序通过 Action 持久化，旧项目缺失可选字段时兼容读取。克隆是后端账户命令，不自动改默认或旧片段，不等同生成任务或项目撤销。子窗口具有自己的导航、字段草稿、分页与播放位置，不复制可写项目状态；模型能力由共享声明渲染，排序和叠加使用现有包。
- 桌面边界：Electron 是本地宿主；GUI HTTP Action 进入同一 `Workbench` / `ActionExecutor`。正式项目 CLI / Agent 适配器仍待接线；诊断 CLI 仅复用模型执行内核，不等于当前项目的 Action 入口。
- 项目及系统拖拽：既有项目文件和空文件夹共用主窗口根的唯一进入路径，由容器内容决定打开或初始化，不增加按钮、菜单或合并选择。库的媒体导入、内部对象关系与 Viewer 当前媒体的原生拖出继续使用各自边界；项目切换先隔离旧会话，不能靠客户端改写 projectId 移接请求。

## 验证与边界

`npm run typecheck`、`npm test`、`npm run test:ui`、`npm run test:desktop` 分别验证类型、核心业务、浏览器手势及原生窗口。测试不调用付费生成。

1.1 的 91 项核心测试及 1.2 的类型检查、12 项浏览器交互测试和原生桌面测试作为历史证据保留在[哲学对齐记录](philosophy-alignment.zh-CN.md)。其中“库打开后主窗口禁用”和库内镜像关系面属于已被 1.3 纠正的旧实现，不能作为新窗口模型通过证据。1.3 的类型检查、96 项核心测试、12 项浏览器交互测试及原生桌面验证通过，覆盖共同窗口宿主、非模态工作窗口、双向对象拖拽及各窗口局部详情隔离。原生跨窗口测试用真实鼠标拖起来源对象，再以 Chromium drag 事件向另一原生窗口投放；未自动化 Windows 屏幕坐标间的完整系统鼠标拖动。“不增加常驻控件”描述的是 1.3 当轮范围，1.6 已按用户要求新增上下文控件，不用旧结论限制当前基线。

跨窗口对象 broker 已实现并通过会话、来源与目标校验、过期/主动取消、删除/关闭、非法及重复 token 回归。项目文件及目录拖入打开已完成；1.5 的类型检查、152 项核心测试、19 项浏览器交互测试和原生验证作为该轮历史记录保留，覆盖文本编辑、普通媒体放置及真实时长、只读文本读取、主窗口 Files 入口、素材库拒绝目录、动态项目 ID，以及原有窗口间双向对象关系和重启恢复，不能冒充后续新增能力验证。系统输入的原生自动化采用 Chromium / CDP 投放真实磁盘 File，Viewer 导出使用真实鼠标触发原生 startDrag；这不等于已自动化 Windows Explorer 与外部应用之间完整屏幕坐标拖拽。1.5 记录见[本地时间线与扩展边界](local-timelines-and-extension.zh-CN.md)，1.6 结果及测试边界由[声纹、输入、分组与叠加预览](voices-inputs-groups-and-composition.zh-CN.md)单独记录，1.7 见[共享资源与人工输出](shared-resources-and-manual-output.zh-CN.md)；供应商声音目录和克隆测试使用模拟响应，不读取或创建真实账户资源。

完整撤销重做、插件版本迁移与缺失插件占位、正式项目 CLI / Agent 编辑适配器、共享 Action 能力查询与完整时间线合成导出仍待实现；只读文本 CLI 和多轨叠加预览已完成。原生文件拖出支持 Viewer 当前唯一生效的媒体文件，尚不进行整条作品的合成导出；该文件导出边界与窗口间对象关系 broker 不混用。本轮继续源码开发，Windows 可执行文件未重新打包；旧版本安装包不会因此自动更新。
